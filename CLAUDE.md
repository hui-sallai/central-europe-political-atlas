# Central Europe Political Atlas — working notes for Claude Code

Static research website (Chinese UI) about ten Central/South-East European countries, deployed to GitHub Pages at
https://hy-central-europe-analysis.org via `.github/workflows/deploy-pages.yml` on every push to `main`.

## Stack
- Next.js 16 (App Router, `output: "export"` static site) · React 19 · TypeScript · Tailwind CSS 4 (`@layer base` for element defaults).
- Runtime dependencies are only `next`, `react`, `react-dom`. Keep it that way; test tooling may go in devDependencies.
- Charts are hand-written SVG (`src/components/ResearchTimeSeriesChart.tsx` and friends) — no chart libraries.
- Node 24 + pnpm. Some validators (panel LP, VAR research) need the Python venv with numpy/scipy on `PATH`.

## Directory map
- `src/app/` — routes: `/` (page.tsx), `countries/[slug]`, `data`, `map`, `models`, `scenarios`, `news`, `methodology`,
  `historical-extension`, `legal`, `privacy`, plus `robots.ts` / `sitemap.ts`. `layout.tsx` holds site-wide metadata.
- `src/components/` — page workbenches (`DataExplorerV11`, `MacroDriverWorkbench`, `LocalProjectionWorkbench`,
  `PanelLocalProjectionWorkbench`, `ComparativeSpatialWorkbench`, `VarWorkbench`, …) and shared UI (`ResearchTimeSeriesChart`).
- `src/lib/` — data access and engines (`varEngine.ts`, `localProjectionEngine.ts`, `panelEngine.ts`, `networkEngine.ts`,
  `timeSeriesTransforms.ts`, …), release metadata (`releaseMetadata.ts`), weekly news (`weeklyNews/`).
- `src/data/` — canonical research data and frozen research outputs (JSON). `public/research-data/` — exported copies,
  runtime JSON for the browser and the research package; regenerated by `scripts/export-research-data.mjs`.
- `scripts/` — acquisition, research pipelines and the validation chain (`validation/`, `release/`, `security/`,
  `data-coverage/`, `historical-*/`, `serbia-sors/`, `var-*`, `panel-local-projections/`, `local-projections/`, …).
- `docs/` — longer methodology notes. `CHANGELOG.md` — release history.

## Commands
| Task | Command |
|---|---|
| Dev server (http://localhost:3000) | `pnpm dev` |
| Site-only build (fast, no validators) | `pnpm build:site` |
| Full release build | `pnpm build` — secret scan + ~35 validators + export + `next build` + UI/release checks; several minutes, needs the Python venv |
| Lint / types | `pnpm lint` · `pnpm typecheck` |
| Release checks on `out/` | `pnpm release:validate` |
| UI wording rules | `pnpm ui-language:qa` |
| UI regressions (CTA contrast, tables, charts) | `pnpm ui:regression-validate` (needs a fresh `out/`) |
| Data coverage / history stores | `pnpm data-coverage:validate` · `pnpm historical-annual:validate` · `pnpm historical-monthly:validate` · `pnpm historical-regional:validate` · `pnpm serbia-audit:validate` |
| Weekly news | `pnpm news:validate` |
| Research-data export | `node scripts/export-research-data.mjs` (rewrites timestamps in `public/research-data/`; revert unrelated files before committing) |

Per-change gate used in this repo: `pnpm lint && pnpm typecheck && pnpm build:site && pnpm release:validate`.
`release:validate` checks `out/` against canonical data, so first regenerate the export exactly as the full build does —
`node scripts/export-research-data.mjs && node scripts/release/build-research-package.mjs` — then, after the gate,
restore the tree with `git checkout -- public/research-data src/data/analysis/advanced_analysis_validation_summary.json`
(the deploy workflow regenerates these files itself; committed copies may lag and must not be edited by hand).

## Research-boundary rules (non-negotiable)
1. Never change research data, frozen results or research conclusions. Only UI, metadata, tooling and new tests may change.
2. Never change research wording: no causal or predictive language ("影响/导致/预测/风险" style claims) beyond what the
   published methodology states; missing and pending values are never shown as 0 (use "—" or the hatched no-data style).
   All new UI text must pass `pnpm ui-language:qa`.
3. Keep runtime dependencies to next/react/react-dom; charts stay hand-written SVG.

## Frozen / do-not-edit
- Everything under `src/data/**` and `public/research-data/**`, except:
  - `src/data/release.json` — only when cutting a release (see below);
  - `src/data/events/**` and `src/lib/weeklyNews/**` — only through the weekly news workflow.
- Hash-registered outputs: `src/data/analysis/v173_frozen_output_hashes.json` (86 records, e.g. `varEngine.ts`,
  `timeSeriesTransforms.ts`, `varSpecifications.ts`, `networkEngine.ts`), `src/data/high-frequency/snapshots/snapshot_manifest.json`,
  and every `*preregistration*`, `*closure*`, `*simulation*` file and SHA-256 registry under `src/data/` and `scripts/`.
- Descriptive history stores (`src/data/historical/**`, `src/data/serbia/**`) are reproducible from archived raw
  extracts; their validators fail if a value is edited by hand. Never zero-fill missing observations.
- Formal model samples, readiness files and model registries must not change without a preregistered, owner-approved decision.

## Release process
1. The version string lives in `src/data/release.json` (`version`, `release_date`, `citation_key`); `src/lib/releaseMetadata.ts`
   only reads it. Footer, methodology, citation, platform metadata and the research package all derive from it.
2. Add a dated entry at the top of `CHANGELOG.md`.
3. Run the full `pnpm build`, then revert incidental timestamp changes under `public/research-data/`.
4. Commit. Push only with explicit owner approval ("推送上线"); the Pages workflow deploys `main`.

## Running locally
- macOS / Linux: `pnpm install` then `pnpm dev` (or `pnpm build:site` and serve `out/` statically, e.g. `npx serve out`).
- Windows: double-click `run-dev.bat` (dev server) or `run-preview.bat` (production preview); PowerShell users can run
  `./start-dev.ps1`, which logs to `dev-server.log` / `dev-server.err.log`. Keep these launchers.

## Conventions
- Match surrounding code style; comments are sparse and explain why.
- UI is Chinese; keep numeric formatting via `toLocaleString("zh-CN")` and `tabular-nums` (`.metric-number`).
- Before committing: secret scan (`node scripts/security/check-public-secrets.mjs`) and no personal local paths in the diff.
- Never push or deploy without explicit owner approval.
